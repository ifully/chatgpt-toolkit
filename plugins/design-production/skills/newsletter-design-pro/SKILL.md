# Newsletter Design Pro

## Design constraints
- Define the subject and preheader, information priority, sender identity, CTA, footer, legal requirements and actual sending platform.
- Email is not a web page. Favor robust table-based markup generated by MJML and constrained styles rather than advanced browser-only CSS.
- Ensure working image hosting, meaningful alt text, readable 1-column mobile composition, 44px-ish target size guidance and a plain-text alternative for sending platforms.
- Include unsubscribe and sender identification where required; this example has placeholders and **must not be sent as-is**.

## Implementation
- Edit `templates/newsletter.mjml`, then run `node tools/render-newsletter.mjs`.
- The tool compiles with the installed `mjml` package, fails for MJML errors, and writes an HTML file to `out/`.
- Store real asset URLs and live unsubscribe links only at authorized deployment time, not in public source control if they expose secrets.
- For React Email workflows, use it as an alternate compiler; it is **not** bundled with the uploaded six sources.

## Verification
- Run `python tools/qa.py` to detect placeholder destinations, missing alt text, malformed attributes and obvious structural mistakes.
- Check email CSS support with Can I Email (online reference) and run real sends/previews in Gmail, Outlook and Apple Mail or an equivalent email testing service. Browser rendering is *not* a substitute.
- Verify tracking, consent and privacy notices with the organization’s actual policy and jurisdiction.
- Read `../design-quality-audit/SKILL.md`; do not claim full cross-client compatibility until tested.
